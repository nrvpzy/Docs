
## Key Native Query

In `AuthorizationRepository`:

```sql
SELECT DISTINCT RA.AUTHORIZATION_CODE
FROM ROLE_AUTHORIZATIONS RA
JOIN USER_ROLES UR ON RA.ROLE_NAME = UR.ROLE_NAME
WHERE UR.USER_ID = :userId
```

This means:

```text
Given a user ID
   |
   v
Find user's roles from USER_ROLES
   |
   v
Find authorizations mapped to those roles from ROLE_AUTHORIZATIONS
   |
   v
Return distinct authorization codes
```

```text

   - sidebar menu items
   - protected routes
   - page-level access
   - action buttons
   - in-page controls

9. Backend services remain protected by JWT security.
```

## Strong Interview Explanation

> RBAC was implemented using users, roles, and authorization codes. Authorization codes represented fine-grained permissions such as access to a page or action. Users were mapped to roles, roles were mapped to authorization codes, and the UI consumed the resolved authorization list to show or hide routes and buttons. The backend services were still protected by JWT validation, so UI-level authorization was not the only security control.

# 28. One Strong System Design Summary

You can say this in an interview:

> The system used a microservices architecture with a Next.js frontend and Spring Boot backend services. Authentication was handled through an ADFS/OIDC bridge. After login, backend services validated JWTs using OAuth2 resource-server configuration. RBAC was handled by the admin service using users, roles, and authorization codes. The UI consumed these authorization codes to filter routes, sidebar items, and action buttons.
>
> The MCP vehicle order service handled the core business lifecycle. It exposed APIs for creating, updating, cancelling, returning, and fetching orders. Business validations were separated into rule classes, and status transitions were centralized in a dedicated status calculation service. Order data was persisted across multiple domain entities such as vehicle details, user details, finance details, options, dealer-fitted accessories, workflow activity, and order history. For operational screens, we used reusable filtering, sorting, and pagination both in the frontend and backend.
