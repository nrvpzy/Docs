## Business Story of the Application

This application can be explained as an **internal fleet / vehicle order management platform**.

Its purpose was to help business teams manage the complete lifecycle of employee or fleet vehicle orders from one centralized system instead of relying on emails, spreadsheets, SAP/Vista portals, and manual follow-ups.

---

# 1. What the Application Is

The application is a **FleetHub / vehicle order management platform** used by internal business teams to manage vehicle orders end to end.

It brings together multiple workflows:

- employee vehicle order creation
- vehicle allocation
- order modification
- cancellation
- vehicle return
- spare vehicle handling
- vehicle status dashboards
- SAP/Vista-style operational processing
- finance/report generation
- employee lookup
- role-based access control

In simple terms:

> It is a centralized platform where operations teams can create, track, update, and complete vehicle orders.

---

# 2. What Problem It Solves

Before this platform, the process was fragmented.

Teams were using:

```text
emails
Excel sheets
manual approvals
SAP/Vista portals
shared trackers
file uploads
manual status updates
```

This created issues like:

## Slow processing

A vehicle order might require input from several teams:

- operations
- employee/HR team
- allocation team
- finance team
- SAP/Vista users
- admin team

If everything happens through emails and spreadsheets, progress is slow.

---

## No single source of truth

One team might track order status in Excel.

Another team might rely on SAP.

Another might have updates from Vista.

Another might communicate through email.

So nobody has one reliable place to answer:

> What is the current status of this order?

---

## Manual errors

Manual workflows can cause:

- duplicate vehicle orders
- wrong employee details
- incorrect vehicle assignment
- outdated vehicle/pricing information
- missing return mileage
- wrong report data
- unauthorized users performing actions

---

## Poor visibility

Managers and operations users need quick answers:

- How many orders are awaiting allocation?
- Which vehicles are ready for handover?
- Which orders are delayed?
- Which vehicles have been returned?
- Which employee has an active order?
- Which orders need SAP/Vista processing?

Without a centralized application, answering these questions takes time.

---

# 3. What the Application Does

The application gives teams a controlled digital workflow.

## 3.1 Creates vehicle orders

Users can create an order for an employee or business user.

The order includes:

- employee information
- vehicle selection
- finance information
- vehicle options
- dealer accessories
- required dates
- pickup/drop details

---

## 3.2 Validates order data

Before saving an order, the system checks business rules.

For example:

- Is the employee information valid?
- Does this employee already have an active order?
- Is the selected vehicle available?
- Are required details present?

This prevents bad data from entering the process.

---

## 3.3 Tracks order status

Every order has a status.

Example statuses:

- awaiting allocation
- submitted to build
- ready for handover
- cancelled
- returned
- with customer

The status tells operations teams:

> What stage is this order currently in?

---

## 3.4 Supports allocation

Some orders need to be matched with available vehicles.

The application helps allocation teams:

- view orders awaiting allocation
- filter by vehicle type/configuration
- assign or allocate orders
- move orders to the next stage

---

## 3.5 Handles modification and cancellation

If details change, authorized users can modify the order.

If the order is no longer needed, it can be cancelled.

Both actions are controlled and tracked.

---

## 3.6 Handles vehicle return

When a vehicle comes back, users can record:

- return mileage
- return registration number
- return date/details

The system updates the order and vehicle history.

---

## 3.7 Maintains order history

Every important action is recorded.

Examples:

- order created
- order modified
- order allocated
- order cancelled
- vehicle returned
- file processed
- report generated/exclusion applied

This gives an audit trail.

So if someone asks:

> Who changed this order and when?

The system can answer.

---

## 3.8 Supports SAP/Vista-style workflows

The application does not necessarily replace SAP or Vista.

Instead, it centralizes the operational work around them.

It can:

- prepare orders for export
- process returned files
- update order numbers/statuses
- handle error files
- generate reports
- exclude records from reports

This reduces manual reconciliation.

---

## 3.9 Generates reports and dashboards

The application provides:

- order status dashboards
- monthly order summaries
- allocation views
- SAP/Vista reports
- finance reports
- spare vehicle reports
- vehicle data reports

This improves visibility for teams and managers.

---

## 3.10 Controls access

Different users need different access.

For example:

- operations users can manage orders
- finance users can view finance reports
- admin users can manage roles
- SAP users can generate SAP reports
- some users can only view data

The system uses role-based access control so users only see and perform actions they are allowed to.

---

# 4. How It Works at a Business Level

The simplified workflow is:

```text
User logs in
   ↓
System checks what they are allowed to do
   ↓
User creates or searches an order
   ↓
System validates the data
   ↓
Order is saved and assigned a status
   ↓
Operations team manages allocation
   ↓
SAP/Vista processes are handled through reports/uploads
   ↓
Vehicle is handed over
   ↓
Vehicle is eventually returned
   ↓
History and reports remain available
```

# 5. Main Users of the Application

The application is used by different internal teams.

## Operations team

Creates, updates, allocates, cancels, and returns orders.

## Allocation team

## Finance team

## Admin users

Manage users, roles, and permissions.

## Managers

Use dashboards and reports to monitor the process.
