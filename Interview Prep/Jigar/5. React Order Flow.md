# React Frontend — Order Management Flow and Pages

This explains the frontend side of the FleetHub / vehicle order management application in terms of **React**.

The frontend’s job was to give operations users a clean interface to:

```text
create orders
view/search orders
edit orders
allocate vehicles
cancel orders
return vehicles
view history
see dashboards
control access based on roles
```

Memory hook:

```text
Login → Permissions → Dashboard/List → Create/Edit/Allocate/Return → History
```

# 3. Frontend Login and Permission Flow

After SSO login, the frontend loads protected app state.

```text
User opens app
   ↓
AuthContext checks session
   ↓
If authenticated, fetch current user
   ↓
PermissionContext fetches user permissions
   ↓
Sidebar/routes/buttons filtered
   ↓
User sees allowed screens
```

Permissions control UI like:

```text
VIEW_ORDER → show order list
CREATE_ORDER → show create order page/button
MODIFY_ORDER → show edit action
RETURN_VEHICLE → show return button
CANCEL_ORDER → show cancel button
VIEW_ALLOCATION → show allocation page
```

# 6.3 Edit / Modify Order Page

```text

```

---

## Flow

```text

   ↓

   ↓

   ↓

   ↓

   ↓

   ↓

   ↓
Show loading
   ↓
On success → toast + refresh/redirect
   ↓
On error → show validation message
```

---

## Important frontend concerns

```text
pre-populating nested form data
handling disabled fields based on status
showing current status
showing validation errors
preventing double submit
```

Some fields may be disabled depending on order status.

Example:

```text
CANCELLED order → no edit
RETURNED order → limited edit
```

---

## Interview explanation

> The edit page reused much of the create-order form but preloaded the existing order and handled status-aware UI behavior. It submitted only the modified order payload and refreshed the order view after update.

# 11. Performance Considerations

## Server-side pagination

Do not load all orders.

```text
page + page_size sent to backend
```

## Debounced filters

Search fields should debounce API calls.

```text
user types → wait 300ms → call API
```

## Memoized columns/actions

Avoid unnecessary re-renders in large tables.

## Lazy-loaded pages

Load heavy pages/charts only when needed.

## Cache reference data

Cache stable dropdown data:

```text
brands
models
derivatives
colours
options
```
