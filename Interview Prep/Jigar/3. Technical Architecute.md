# Technical Playbook — React + Python FastAPI FleetHub Platform

This playbook explains the same vehicle/fleet order management application as a **full-stack React + FastAPI system**.

The goal is to help your friend explain the project confidently as a balanced full-stack developer: backend APIs, frontend workflows, authentication, RBAC, dashboards, filtering, and deployment.

```text

   ↓
```

# 11. Dynamic Filtering / Search

The frontend sends filter criteria like:

```json
{
  "filters": [
    { "field": "status", "operator": "eq", "value": "AWAITING_ALLOCATION" },
    { "field": "brand", "operator": "eq", "value": "JAGUAR" },
    { "field": "created_at", "operator": "gte", "value": "2024-01-01" }
  ],
  "sort": [{ "field": "created_at", "direction": "desc" }],
  "page": 1,
  "page_size": 25
}
```

FastAPI receives it using Pydantic schemas.

Backend converts filters into SQLAlchemy conditions:

```text
status == value
brand == value
created_at >= value
field.ilike("%value%")
field.in_(values)
```

Then applies:

```text
WHERE conditions
ORDER BY
LIMIT/OFFSET
```

Response:

```json
{
  "items": [],
  "page": 1,
  "page_size": 25,
  "total": 250,
  "total_pages": 10
}
```

Problems solved:

- no need for many separate search APIs
- supports complex admin queries
- faster large-data search
- consistent grid behavior

# 12. Pagination vs Caching

For order lists, pagination is better than caching because:

```text
order data changes frequently
filter combinations are huge
users need fresh data
payloads can be large
database indexes can filter efficiently
```

Caching is better for reference data:

```text
brands
models
derivatives
colours
options
permission metadata
```

Good explanation:

> We used server-side pagination/filtering for transactional order data and caching for relatively static reference data.

# 20. Key Interview Summary

A strong technical summary:

> The system was built as a React + FastAPI microservices platform. The frontend handled dashboards, order workflows, role-aware navigation, forms, tables, and consistent UI states. The backend exposed FastAPI services for order lifecycle, employee data, vehicle master data, RBAC, authentication, and finance reports. FastAPI APIs used Pydantic for validation, SQLAlchemy for persistence, dependency injection for auth/permissions, and dynamic query builders for filtering and pagination. SSO was handled through OAuth2/OIDC with ADFS, and RBAC controlled both frontend visibility and backend authorization. The platform converted a manual fleet order process into a secure, auditable, API-driven workflow.
